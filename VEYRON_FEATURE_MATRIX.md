# Veyron WM feature matrix

Audit snapshot: 2026-11-21. State is based on the current local worktree at `outputs/Veyron-WM`, branch `main`, not the older `Veyron-WM-finish` checkout. `IMPLEMENTED` means real compositor-connected behavior is evidenced; no item is marked `IMPLEMENTED` in this snapshot.

| State | Meaning |
|---|---|
| IMPLEMENTED | Complete, integrated and validated in the actual compositor. |
| PARTIAL | A useful model/prototype exists, but one or more required integration/behavior gates are absent. |
| MISSING | No implementation was found in the inspected tree. |
| BROKEN | An existing implementation is known to violate expected behavior. |
| BLOCKED | Required external dependency/capability prevents implementation in this environment. |
| UNVERIFIED | Evidence is insufficient to decide whether an existing implementation works. |

Evidence boundary: source inspection found a Smithay 0.7 nested winit/GLES binary with xdg-shell, SHM and seat setup, plus standalone window/layout/workspace models. The model tests are documented as 25 historical passes, but were not rerun in this audit because obtaining the temporary Nix compiler estimated 558.5 MiB download / 1.9 GiB unpacked; that fetch was interrupted to protect the 4 GiB machine. The current compositor executable and real-client runtime have no verified build/smoke evidence. `PARTIAL` is not production support.

Each feature row names its current code owner, concrete gap, proving test, and next step. Dependencies and test gates are repeated where a feature is independent so the matrix remains actionable.
